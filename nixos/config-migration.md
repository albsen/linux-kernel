# Kernel Configuration Migration (Phase 5)

How the known-working **Linux 7.0.12** NixOS configuration
(`kernel_7.0.12/kernel-configs/working_el2.config`) was migrated to the
**Linux 7.3** tree and saved as `nixos/working_el2-7.3.config`.

## Method (per the brief)

1. Copied the 7.0.12 working config into an out-of-tree build directory
   (`.build/.config`).
2. Ran the **7.3** kernel's `olddefconfig` against it:
   ```
   nix develop
   make O=$PWD/.build ARCH=arm64 LLVM=1 olddefconfig
   ```
   `olddefconfig` keeps every existing symbol value, resolves the new 7.3
   Kconfig symbols to their defaults, and drops symbols the 7.3 Kconfig no
   longer defines.
3. Ran `make O=… LLVM=1 rustavailable` → **`Rust is available!`** (this is what
   sets `CONFIG_RUST=y` / `CONFIG_RUST_IS_AVAILABLE=y`).
4. Promoted the result to `nixos/working_el2-7.3.config`.
5. Compared original vs migrated (EL2/KVM/Rust/boot focus).

## Toolchain used for the migration

Run **inside the project's own `nix develop`** (see `flake.nix`), so the
migrated config reflects exactly what the Nix build will use:

| Tool | Version | Source attr |
|---|---|---|
| clang / lld / llvm | 21.1.8 | `clang`, `llvmPackages_21.{lld,llvm}` |
| rustc | **1.99.0** | `rustc-unwrapped` |
| bindgen | 0.72.1 | `rust-bindgen-unwrapped` |
| pahole (dwarves) | 1.32 | `pahole` |
| flex | 2.6.4 | `flex` |
| bison | 3.8.2 | `bison` |
| dtc | 1.8.1 | `dtc` |

`RUST_LIB_SRC` = `rustPlatform.rustLibSrc`; `LIBCLANG_PATH` = `pkgs.libclang`
(both set in the devShell; the Nix `linuxManualConfig` path uses the same
values internally).

## What changed 7.0.12 → 7.3

Overall the migration is small and clean. From a full-symbol diff
(9,243 → 10,557 active symbols; the increase is new Kconfig options that
didn't exist in 7.0.12):

| Category | Count | Detail |
|---|---|---|
| **Value changed** | 15 | only **Rust toolchain version**: `RUSTC_VERSION` `109500 → 109900`, `RUSTC_VERSION_TEXT` `rustc 1.95.0 → rustc 1.99.0`; rest are minor non-EL2 defaults |
| **Removed** | 127 | of these only 2 are Rust-related (`RUSTC_HAS_COERCE_POINTEE`, `RUSTC_HAS_SLICE_AS_FLATTENED` — feature-detection flags dropped by the newer rustc). The rest are symbols the 7.3 Kconfig simply renamed/removed. **No EL2/KVM capability removed.** |
| **Added** | 1,441 | mostly brand-new 7.3 Kconfig options defaulting to `#not set`. **EL2-relevant additions:** `CONFIG_NVHE_EL2_DEBUG` (`#not set`), `CONFIG_ARM_PKVM_GUEST` (`#not set`), and new `EFI_*` debug options. These are *additions*, not redefinitions. |

## EL2 / KVM / Rust — preserved (verified present in BOTH configs)

```
CONFIG_KVM=y
CONFIG_KVM_COMMON=y
CONFIG_KVM_MMIO=y
CONFIG_KVM_VFIO=y
CONFIG_KVM_GENERIC_HARDWARE_ENABLING=y
CONFIG_KVM_GUEST_MEMFD=y
# CONFIG_NVHE_EL2_DEBUG is not set     (7.0.12 had no such option; 7.3 adds it)
CONFIG_SYS_HYPERVISOR=y
CONFIG_ARM64_AMU_EXTN=y
CONFIG_ARM64_EPAN=y
CONFIG_ARM64_ERRATUM_1418040=y
CONFIG_ARM64_ERRATUM_2645198=y
CONFIG_ARM64_ERRATUM_1463225=y
CONFIG_KERNEl_MODE_NEON=y

CONFIG_RUST=y
CONFIG_RUST_IS_AVAILABLE=y
CONFIG_RUSTC_VERSION=109900          (was 109500 — toolchain bump only)
CONFIG_RUSTC_LLVM_VERSION=210108
```

**Interpretation:** the EL2/KVM functional surface is **byte-for-byte the same**
in the migrated 7.3 config as in the working 7.0.12 config — the only
substantive change is the Rust toolchain version (1.95 → 1.99, matching the
pinned nixpkgs). Nothing EL2-related was lost; 7.3 only *gains* a few new
EL2/hypervisor debug options (all off by default).

## Rust support (preserved)

- The brief forbids silently disabling Rust. `olddefconfig` with **no** rustc
  on PATH would have dropped `CONFIG_RUST` to `#not set`. Running the migration
  **inside `nix develop`** (rustc 1.99 on PATH) preserved
  `CONFIG_RUST=y` / `CONFIG_RUST_IS_AVAILABLE=y`, and `make rustavailable`
  confirmed **`Rust is available!`**.
- The final `working_el2-7.3.config` therefore keeps Rust enabled with
  `RUSTC_VERSION=109900`, `RUSTC_LLVM_VERSION=210108`, and the 7.3-specific
  `RUSTC_*` feature-detection flags.

## Boot-critical symbols (preserved)

```
CONFIG_EFI=y
CONFIG_EFI_STUB=y
CONFIG_BLK_DEV_INITRD=y
CONFIG_BTRFS_FS=y          (root fs)
CONFIG_NVME / NVMe + crypto (root on LUKS/Btrfs)
```

## Result

- `nixos/working_el2-7.3.config` — complete, self-consistent 7.3 config
  (12,723 lines), generated by the 7.3 `olddefconfig`, Rust enabled, all
  KVM/EL2/EFI/initrd symbols intact.
- This is the `configfile` consumed by the `linuxManualConfig` in `flake.nix`
  (Phase 6), so the Nix build and the manual `make` path use the **same**
  configuration.

## One deliberate config change: `CONFIG_NETWORK_SECMARK=y`

The 7.0.12 working config had `CONFIG_NETWORK_SECMARK` **unset** (`#not set`).
In the 7.3 tree this left the build broken: `security/apparmor/lsm.c`
*defines* `aa_secmark_enabled()` inside `#ifdef CONFIG_NETWORK_SECMARK`
(lsm.c:1864–1909) but *calls* it from `apparmor_socket_sock_rcv_skb()`
(lsm.c:1958) **outside** that guard, and dereferences `skb->secmark`
(a `skbuff.h` member gated by the same symbol) at 1972/1974/2003/2004 —
also unguarded. With `NETWORK_SECMARK=n` these are implicit-declaration and
no-member compile errors in `security/apparmor/lsm.o`.

Setting `CONFIG_NETWORK_SECMARK=y` (and re-running 7.3 `olddefconfig`)
resolves it. This is a one-line config flip, not a source patch — and it is
the same value any AppArmor-enabled 7.3 build uses (jglathe's build has it on).

## Outstanding

- `CONFIG_NVHE_EL2_DEBUG` is a new (off) 7.3 option — left at its default
  `#not set`, matching the running 7.0.12 behaviour (no NVHE debug enabled).
- No `CONFIG_ARM64_VHE`-style symbol exists or is needed (VHE is runtime
  detected); see `boot-el2.md` §2.
